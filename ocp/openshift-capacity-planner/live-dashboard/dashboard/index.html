📊 Worker Node Pressure

CPU/Mem Request % = scheduled demand vs allocatable (scheduler pressure). CPU/Mem Used % = real consumption from oc adm top nodes. High Request% with low Used% = over-provisioned workloads (rightsizing opportunity). High Used% = actual saturation risk.

🔧 Desired Replica Demand

Primary planning signal (Red Hat practice #6): spec.replicas × template requests = what the cluster must support if all workloads are fully scaled. Compare against Running requests in the Namespaces tab to identify scheduling gaps. Replicas=0 is intentionally scaled down and adds no demand until the configured replica count increases.

⚠ Misplaced Dedicated Workloads

Pods whose nodeSelector or nodeAffinity targets a dedicated taint key (e.g. app=sas, dedicated=uipath) but are running on shared nodes. Toleration-alone is not flagged — that is common on operators. These pods are likely using shared capacity they weren't supposed to consume.

Storage Capacity & Inventory

A Bound PVC is not automatically unused. Evidence combines active pod mounts, Deployment/StatefulSet/CronJob templates, Job templates, VolumeAttachments, PV state, and filesystem metrics when available. Filesystem Used is shown only when the CSI/kubelet exposes kubelet_volume_stats_*; unavailable does not mean zero use. Claims without a current workload reference are validation items, not deletion recommendations; confirm ownership, backups, and retention before action.
