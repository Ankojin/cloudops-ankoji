Red Hat OpenShift capacity practices used here
1. Capacity = sum of pod Requests vs node Allocatable (scheduler does not oversubscribe Requests).
2. Overcommit means Limits > Requests on pods — it does not mean scheduling more Requests than Allocatable.
3. Prefer always setting CPU/memory Requests; avoid CPU Limits when possible; size Requests from observed average usage.
4. Plan scale-out when Request/Allocatable approaches ~80% (OpenShift monitoring guidance / autoscaler pressure).
5. DaemonSets consume capacity on every new node — subtracted from net capacity per node.
6. Desired replicas (Deployment/STS) are the primary planning signal; Running pods are the current-pressure signal.
7. Usage metrics from oc adm top (metrics-server) show real consumption vs Requests for rightsizing.
CSVs in the output directory have full detail for Excel (including 14_node_metrics.csv).
